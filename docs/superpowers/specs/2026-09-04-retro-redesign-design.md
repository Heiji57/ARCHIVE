## 2. Phase 1 — 회고 에디터

### 2.1 화면 구조

카드(`section-card`) 껍데기를 버리고 **한 단 문서 + 우측 각주 레일**로 전환한다.

```
┌─ 상단 앱 헤더(기존 그대로, 이번 범위 아님) ────────────────────┐
├──────────────────────────────────────────────────────────────┤
│  ‹ 모든 회고록                                                 │
│  ┌── 본문 컬럼 (max 720px) ───────┐  ┌─ 레일 (max 320px) ──┐  │
│  │ [일간] [ARCHIVE / 9월 ▾]  날짜  │  │ 자동 저장 안내        │  │
│  │ ＜제목 입력＞                    │  │ 동기화 상태 Pill      │  │
│  │ 힌트: 비워두면 …로 저장됩니다     │  │ [GitHub에 Push]      │  │
│  │ (배너: 미연결 / Push 대상 없음)   │  │ [전체 화면으로 쓰기]   │  │
│  │ ── 완료한 작업 ──────────────    │  │ ── 이 회고의 재료 ──  │  │
│  │ ── 오늘의 커밋 ──────────────    │  │ 완료한 작업 · 커밋 ·  │  │
│  │ ── 회고 본문(RichEditor) ────    │  │ 본문 블록            │  │
│  └────────────────────────────────┘  └────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

- 본문/레일은 flex-wrap. 좁은 화면(≤900px)에서는 레일이 본문 아래로 내려가고 sticky를 해제한다.
- 레일은 `position: sticky; top: 16px`.

### 2.2 영역별 사양

**① 문서 머리**

- **회고 타입**: 현재 엔트리의 타입 1개만 **읽기 전용 pill**로 표시한다.
  - 디자인(3a①/`Daily Retro Editor.dc.html`)은 `일간|주간|월간|연간` 4개 세그먼트를 그렸지만, **엔트리의 `retroType`은 변경할 수 없다**(주간/월간/연간은 `/summaries`가 만든 AI 요약 엔트리다). 4개를 그리면 3개가 죽은 컨트롤이 되므로 현재 타입만 표시한다.
- **폴더**: `entry.folderId`가 가리키는 폴더 경로(`부모 / 자식`)를 버튼으로 표시하고, 누르면 폴더 목록 드롭다운. 선택 시 기존 `moveEntryToFolder(entryId, retroType, folderId)` 호출. "폴더 없음" 항목으로 루트 이동 가능.
- **날짜**: `formatFullDate(fromDateKey(entry.dateKey))`, 모노 폰트.
- **제목**: 큰 입력창(`.retro-doc-title`). `entry.isSummary`면 읽기 전용(현행 유지).
  - `value = entry.title`, `placeholder = 기본 제목`.
  - 힌트 문구: "비워두면 `{기본 제목}`(으)로 저장됩니다".
  - **기본 제목 계산은 FE에도 둔다** — 결정 9(서버가 채움)가 BE에 반영되기 전까지 `createDailyEntry`가 지금처럼 기본 제목을 넣고, 반영 후에는 빈 문자열로 보내면 된다. FE 헬퍼는 두 경우 모두 표시용 폴백으로 쓰인다.

**② 완료한 작업**

- 현행 데이터(`completedTodos`) 그대로, 문서형 목록으로. 우측에 개수.
- 비었을 때: "오늘 완료된 작업이 없습니다." (**"할 일에서 가져오기" 링크는 넣지 않는다** — 결정 10)
- 일간 회고에서만 노출(현행 `isDailyEntry` 분기 유지).

**③ 커밋**

- 문서형 목록: `메시지` + `sha(7자) ↗` 2열. 새로고침 버튼, `@login`, 개수.
- 하단 요약 줄: 커밋이 **모두 같은 저장소**면 `모두 {fullName}`, **여러 저장소**면 `{n}개 저장소`.
- **커밋 행에는 동기화 Pill을 붙이지 않는다.**
  - 디자인(3a④, `Daily Retro Editor.dc.html`)은 커밋마다 `Synced/Pending/미연결` pill을 그렸지만, 이 앱에서 "동기화"는 **회고 문서 1개를 저장소에 push했는지**(`entry.synced` / `githubPush`)를 뜻한다. 커밋은 GitHub에서 읽어온 데이터라 동기화 상태라는 개념이 없다. 원래 지적된 누락(회고 문서의 Synced/Pending/미연결 Pill)은 **레일에 1개**로 복원한다.
- 빈 상태·재연결 안내는 현행 `RetroCommitsSection` 로직 유지.

**④ 회고 본문**

- `RichEditor`를 카드 없이 문서 폭 그대로 렌더. 섹션 헤더는 `회고 본문 · Content` + "Markdown · `/` 명령으로 블록 추가" 힌트.
- 본문 구조("오늘 한 일 / 배운 것 / 내일 할 일 / 느낀 점")는 **저장 필드가 아니라 사용자가 쓰는 마크다운 헤딩**이다. 스키마 변경 없음.
- **체크박스 블록 추가**(결정 13) — 슬래시 메뉴 `할 일 체크박스`, 마크다운 `- [ ] / - [x]` 왕복.

**⑤ 우측 레일**

- 자동 저장 안내(현행 문구 재사용).
- **동기화 상태 Pill 1개**: `synced` → 초록 "GitHub에 동기화됨", 미푸시 → 앰버 "동기화 대기 중", 미연결 → 회색 "GitHub 미연결". (현행 헤더 Pill을 그대로 옮김)
- `GitHub에 Push` 버튼(현행 로직 그대로), `전체 화면으로 쓰기` 버튼(현행 확장 모드, `Ctrl+Shift+F` 유지).
- "이 회고의 재료": 완료한 작업 수 / 커밋 수 / 본문 블록 수.
  - 본문 블록 수는 마크다운 기준 최상위 블록 개수(빈 줄로 구분된 덩어리)로 계산한다. 구조화 필드가 없으므로 디자인 v1의 "작성한 문단 2/4" 같은 진행률은 만들 수 없다.
- **"붙을 주제" 섹션은 넣지 않는다**(결정 7·8).

**⑥ 배너**

- `GitHub이 연결되지 않았습니다` / `Push할 저장소가 지정되지 않았습니다` 2종.
- 기존 `DisconnectBanner`의 문구·표시 조건을 그대로 쓰고 문서형 스타일로만 바꾼다.
- **시안의 "GitHub 연결" / "저장소 선택" 액션 버튼은 Phase 1에서 넣지 않는다.** 위젯에서 설정 화면으로 보내는 라우팅 경로가 없고(라우트 상태는 `App.tsx` 소유), access token을 메모리에 두는 구조라 `<a href="/settings">`로 전체 새로고침을 시키면 세션이 끊긴다. 버튼을 살리려면 `App.tsx → RetrospectivesPage → RetrospectiveStudio → RetroEditor`로 라우트 이동 콜백을 내려야 하며, 이는 별도 후속 작업으로 둔다.

**⑦ AI 요약 엔트리 전용 UI** (`entry.isSummary === true`일 때만)

- 상단에 요약 배너 + `원본으로 되돌리기` 버튼 → 기존 확인 모달(`revertSummaryEdit`).
- `entry.status`가 `pending`/`in_progress`면 진행 배너, `failed`면 실패 배너.
- **일간 회고에는 요약 관련 UI를 넣지 않는다** — 결정 11에 따라 요약은 주간/월간/연간(`/summaries`)에만 존재한다. 디자인의 "✦ 본문 전체 요약" 버튼은 삭제.

### 2.3 디자인 토큰 정합 (결정 16)

- **폰트**: `--font-text`/`--font-display` 맨 앞에 `Pretendard` 추가(한글 렌더링). 모노는 기존 `Commit Mono` 유지 — 시안의 JetBrains Mono는 쓰지 않는다.
- **폰트 크기**: `CLAUDE.md` §10 그대로 — 12 / 16 / 18 + 기존 헤드라인 스케일(21·22·28·`clamp(32,3.4vw,44)`·`clamp(40,5vw,48)`). 시안의 10·10.5·11·13·14·15·17·20·26·30·46px는 **쓰지 않는다**.
  - 시안 → 적용 매핑: 문서 제목 46px → `.t-display-lg`(clamp 32~44), 섹션 헤더 15px → 18px, 본문 16~17px → 16px, 메타/뱃지 10~13px → 12px.
- **여백**: 4px 그리드(`--s-*`). 시안의 9·14·18·22·26·34px는 8/12/16/24/32로 스냅.
- **라운드**: `--r-*`(4/6/8/12/16/24/9999). 시안의 5·7·9·10·11px는 4/6/8/12로 스냅.
- **색**: 시안 hex는 이미 기존 토큰과 같은 팔레트다. 코드에서는 `var(--color-*)`만 쓴다.

## 3. Phase 2 — 주제 뷰 (BE 선행)

### 3.1 결정 4가 강제하는 축소

`content`가 마크다운 문자열 그대로이므로 `1b` 시안에서 아래는 **구현하지 않는다**:

| 시안 요소 | 처리 |
|---|---|
| 문장 끝 출처 각주 뱃지(`회고 7/14`) | **삭제** — 문장↔엔트리 연결 데이터가 없다 |
| "문단 3개 · 출처 6"의 출처 수 | 소스 목록 API(`GET /topics/{id}/sources`)의 `total`로 대체 |
| "잘 된 것 / 계속 걸리는 것" 섹션 | 별도 필드로 만들지 않는다. AI가 마크다운 헤딩으로 쓰면 그대로 렌더될 뿐 |
| 인용구 블록 | 위와 동일 — 마크다운 `>` 인용이 나오면 그대로 렌더 |
| "읽는 데 N분" | 마크다운 글자 수로 FE 계산 (유지) |

출처의 역할은 **상단 메타 + 우측 소스 카드 + "소스 N개 보기"** 가 대신한다.

### 3.2 화면 사양

- **크롬**(3b): 기존 회고 탭 바(`전체/일간/주간/월간/연간/주제`) **유지**. 그 아래 주제 검색 + 주제 pill 목록(이름 + 회고 수) + `+ 새 주제` + `N / 20개 사용`.
- **본문**(1b + 3b): 주제 이름 · 설명 · `설명 편집` · `주제 삭제` / watermark 안내 배너(반영 시점 + 미반영 회고 수 + "다시 정리하면 대체됩니다") / `한눈에` 이하 digest 마크다운 렌더.
- **레일**: `반영 시점` 카드(`MM.DD까지`, 미반영 N개), `소스` 카드(일일/주간 회고 수, 할 일 수).
- **상태 4종**(3c): 빈 상태(정리한 적 없음) / 정리 중(진행률 + 스켈레톤, **중단하기 없음**) / 조회 실패 / 생성 실패(이전 문서 유지 안내 + 다시 시도).
- **모달**: 새 주제 만들기(이름 중복 에러 포함), 주제 삭제 확인, 개수 제한(20개) 안내.

### 3.3 필요한 신규 API

BE 요청서(`docs/be-request-2026-09-04-topics-api.md`) 참고. 요약:

1. `PATCH /topics/{topic_id}` — 이름/설명 수정
2. `GET /topics/{topic_id}/stats` — 회고 수(타입별), 할 일 수(완료/전체), 태그 집계, 기간, **미반영 회고 수**
3. `GET /topics/{topic_id}/sources` — digest에 반영된 소스 목록(페이지네이션)
4. `POST /entries` — 빈 제목일 때 서버가 기본 제목 채우기 (결정 9)
5. (확인) 재생성으로 `status`가 pending이 될 때 기존 `content` 유지 여부

## 4. 후속/미결

- **주간 회고 시안 1장**(결정 15) — 커밋 섹션을 기간 합계로 어떻게 보여줄지가 남아 있다. Phase 1은 일간 기준으로 만들고, 주간/월간/연간은 같은 레이아웃에 커밋/완료작업 섹션만 숨긴 채(현행 `isDailyEntry` 분기) 동작한다.
- **배너 액션 버튼**(§2.2⑥) — 설정 화면으로 가는 라우트 콜백을 위젯까지 내리는 후속 작업.
- Phase 2 계획서는 §3.3의 API가 `api.yaml`에 반영된 뒤 작성한다.
